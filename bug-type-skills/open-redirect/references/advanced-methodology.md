# Open Redirect Methodology

Use this reference to assess redirect trust and chaining.

## Start here: how hunters found this in real reports

1. **Find redirectors in trusted flows.** Login, logout, OAuth, password reset, invitations, payment return, tracking, preview, and deep-link handlers are more useful than generic navigation.
2. **Map parsing and normalization.** Compare relative and absolute forms, path traversal, decoding order, userinfo, scheme-relative values, and redirects generated by downstream services.
3. **Trace every hop.** Record which component creates each redirect and what query, fragment, code, token, or cookie-related behavior survives.
4. **Test the trust consumer.** Ask whether another validator, allowlist, CSP rule, OAuth client, email scanner, or user treats the source domain as safe.
5. **Use a controlled destination and harmless marker.** Do not collect real credentials or tokens.
6. **State the concrete chain.** If nothing sensitive crosses and no trust boundary is abused, treat it as low impact rather than inventing phishing impact.

### Expand the pattern

The valuable lesson from chained reports is that redirect impact belongs to the next system that trusts the redirecting domain. Test that consumer explicitly.

## 1. Redirect inventory

List redirect parameters, login/logout destinations, OAuth callbacks, SSO RelayState, QR URLs, mobile deeplinks, and error redirects.

## 2. Parser checks

Test scheme-relative URLs, encoded slashes, backslashes, userinfo, fragments, IDN, nested URLs, path traversal, trailing dots, and double encoding.

## 3. Trust chaining

Prioritize OAuth code leakage, SSO token leakage, app-link capture, phishing with auth context, SSRF, XSS, and cache poisoning chains.

## 4. Confirmation rules

Show the trusted origin sending a sensitive flow or token-bearing user to attacker-controlled destination.

## 5. Remediation checklist

- Use server-side destination IDs instead of raw URLs.
- Enforce exact allowlists after canonicalization.
- Strip tokens from URLs.
- Do not allow redirects in OAuth callback allowlists.
- Validate mobile and QR redirect targets.

## 6. What successful reports teach

- Reports where an open redirect leads to account takeover, such as CS Money and Uber, show that impact comes from a trusted flow carrying a capability to the redirect—not from the redirect in isolation.
- QR scanners and mobile browsers add camera input, app dispatch, and platform URL parsing to the redirect chain.
- Regex and domain-validation bypass reports show why the validator's string view must be compared with the browser, HTTP client, WebView, or downstream SDK's parsed authority.
- Login/logout redirects can inherit sensitive context through query parameters, fragments, Referer, or ambient authorization state.

## 7. Parser-chain method

Trace:

```text
input encoding -> application decode -> URL parser/normalizer -> allowlist
-> redirect serialization -> browser/WebView/app parser -> final authority
```

Record scheme, username/password, host, port, path, query, fragment, Unicode/IDN form, slash/backslash behavior, and nested redirect parameters at each step. Select mutations that test a known disagreement; do not run an unbounded generic URL list.

Classify destination control precisely:

- external origin;
- attacker-controlled path on an allowed origin;
- custom app scheme or intent;
- same-site but cross-origin sibling;
- internal/server-side redirect only;
- client-side navigation after trusted data is removed.

## 8. Impact-first confirmation

- First prove the final authority with a harmless destination you control.
- Then identify an actual trusted source of a code, token, signed URL, app-link action, security warning bypass, or sensitive Referer.
- Confirm that every edge preserves the capability; many frameworks strip fragments, replace query strings, or consume codes before the open redirect executes.
- Report a standalone redirect at its demonstrated phishing/trust impact when no stronger chain exists; do not claim account takeover from a hypothetical OAuth flow.
